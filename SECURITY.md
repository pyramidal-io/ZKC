# Security Policy

## Reporting a vulnerability

Report suspected vulnerabilities privately through
[GitHub private vulnerability reporting](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing-information-about-vulnerabilities/privately-reporting-a-security-vulnerability)
for this repository. Do not open a public issue containing vulnerability
details.

Reports are triaged against the canonical private development repository. A
fix reaches this repository through a subsequent reviewed snapshot export.

## Scope

In scope:

- soundness or completeness defects in the published Noir circuits;
- cryptographic, privacy, or protocol defects in the canonical specification
  and Python reference implementation;
- conformance or registry behavior that violates a published ZKC guarantee;
- supply-chain weaknesses in the public CI defined in this repository.

Private infrastructure, unpublished implementations, deployments, and
credentials are outside this repository's public scope.

## Disclosure

Please allow a reasonable period for coordinated assessment and remediation
before public disclosure. Reporter credit is provided unless anonymity is
requested.
